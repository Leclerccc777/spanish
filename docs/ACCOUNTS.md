# 学习账号与进度同步

2026-10-20：已实现可运行的账号服务、微信入口和浏览器入口；默认未配置线上账号服务。GitHub Pages 只能托管静态页面，不能保存密码或账号数据库。设置服务地址前，界面会显示“账号服务尚未开通”，本地学习和 JSON 备份照常工作。

## 学习者使用

在“我的 / 学习进度”打开账号入口。账号为 4–32 位字母、数字或下划线，不区分大小写；密码为 10–128 个字符，保留原始空格，不写入本机存储或 JSON 备份。注册会把当前本机学习记录复制给新账号，原记录保留。登录已有账号显示该账号的数据；退出后重新显示原来的本机进度。

词卡、课程、错题、分级练习、表达草稿、日 / 周计划与设置都使用原 version 1 学习记录。保存先写本机，再自动尝试同步，也可点击“立即同步”。离线可继续练习；恢复网络、重新打开应用或点击同步可重试。换设备前确认“已与账号同步”；未同步的草稿只存在原设备。

多台设备都有未同步修改时，不自动合并成绩或丢弃草稿。界面提示冲突，先导出本机 JSON，再选择“使用云端进度”或“使用本机进度”。替换前的本机记录另存一份，可导出 / 复制；服务端也保留上一次云端记录。每端仅保留一个替换前版本，多次替换前应自行导出需要长期保留的版本。手工导入备份是明确替换当前账号进度，也会排队同步。

账号本身没有到期日；登录会话有效期 30 天，过期后退出并重新登录即可，本机待同步进度仍保留。现在没有忘记密码找回或修改密码功能，请妥善保管账号密码。长期保存依赖持续运行的服务、持久化磁盘和异地备份，不承诺无条件“永久不丢失”。

## 本地联调

账号服务需要 **Node.js 22.13 或更新版本，建议 Node.js 24 LTS**（使用内置 SQLite）；package 的开发环境要求同步提高，原有纯静态构建代码仍支持 Node.js 20。无新增运行时依赖。

```sh
npm run dev:accounts
```

打开 `http://127.0.0.1:4173/#progress`。前端与 `/api` 同源，账号数据库在 `.account-data/accounts.sqlite`，目录已被 Git 忽略。重启服务沿用同一文件；不要删除目录后声称账号仍可恢复。普通 `npm run dev` 不启用账号。

## 部署账号服务

1. 为服务准备持久化目录和 HTTPS 域名。单实例运行，反向代理到本机端口；不得把 SQLite 文件放进静态站点、可公开下载的目录或 Git。
2. 用 Node.js 24 启动（下例目录、域名须换成实际值）：

```sh
HOLA_ACCOUNT_DB=/var/lib/hola/accounts.sqlite \
HOLA_ALLOWED_ORIGINS=https://leclerccc777.github.io \
PORT=4174 npm run start:accounts
```

服务只监听 `127.0.0.1`。反向代理将 `https://账号域名/api/` 转发到 `http://127.0.0.1:4174/api/`，保留 `/api/` 路径，限制请求体不超过 8 MB、请求时间 15 秒。服务不使用代理传来的用户 IP；目前每个连接 IP 和每个账号每 15 分钟最多 20 次认证尝试。反向代理后 IP 限流共享同一额度，正式开放前应在可信入口增加按真实用户 IP 的限流并做容量验证，不要直接信任任意 X-Forwarded-For。
3. `HOLA_ALLOWED_ORIGINS` 为逗号分隔的精确网页来源（含协议与非默认端口，不含路径），例如 Pages 来源不带 `/spanish/`。无来源头的微信请求仍需 Bearer 会话认证。拒绝 `Origin: null`；本地离线 HTML 不启用账号功能。
4. 浏览器构建使用 `HOLA_ACCOUNT_API=https://账号域名/api npm run build`。GitHub Pages 工作流读取仓库变量 `HOLA_ACCOUNT_API`；未设置时继续发布纯本地版。这个变量只是公开地址，不包含任何密码或密钥。
5. 微信在 `miniprogram/config.js` 填写同一个 HTTPS `/api` 地址，并在微信后台配置该域名为 request 合法域名。使用自己的 AppID，进行微信官方编译和真机注册 / 登录 / 断网 / 同步验收。地址由开发者配置，学习者不输入服务地址。
6. 配置进程守护、服务监控和持久化备份。SQLite 使用 WAL 与 FULL 同步；备份应调用 SQLite 在线备份接口，或停服务后复制数据库及对应 WAL 文件，再实际演练恢复。不要在运行中只复制 `.sqlite` 而遗漏 WAL。

服务启动时保留现有数据库，不在读写失败时创建空账户记录替换旧数据。服务端密码使用每人随机盐和 scrypt 派生值；会话只存 SHA-256 摘要，随机 Bearer token 保存在客户端，退出时尝试撤销。接口不接收客户端声明的 user ID，只用已认证会话定位用户；日志不得记录密码、请求体或 Authorization。所有线上请求必须经 HTTPS。

## 接口与一致性

- `POST /api/register`：username、password、progress；成功返回会话、用户、进度及 revision。
- `POST /api/login`：username、password；返回同上。重复账号拒绝，错误账号与错误密码使用相同反馈。
- `GET /api/progress`：读取自己的当前记录。
- `PUT /api/progress`：progress 与读取时的 revision。原子条件更新，版本冲突返回 409；不能仅提高版本绕过并发检查。
- `POST /api/logout`：撤销当前会话。

本机访客继续使用 `hola-learning-v1`，账号使用独立 `hola-account-progress-v1:<userId>` 信封，内含 progress、revision、pending；会话另存 `hola-account-session-v1`。学习备份只导出 progress，不含凭据。pending 与进度一起写入，避免写成功却丢失待同步标记；上传期间新增操作保留 pending。退出后的旧网络响应不能切回原账号。登录同账号时已有 pending 不被云端静默替换；未知版本和损坏记录继续阻止普通保存，明确导入兼容备份可以修复并保留替换前记录。

## 验证范围

`tests/accounts.test.js` 使用临时 SQLite 与真实本机 HTTP，验证跨设备客户端、账号隔离、重启、过期、冲突、备份、认证限流及原生页面控制；`tests/account-client.test.js` 验证上传中继续学习、退出后过期响应、断网与未知版本；`tests/e2e/accounts.spec.js` 用真实账号接口完成桌面与手机交互。测试不会把测试账号写入生产数据库。

尚未部署生产账号 API、绑定实际域名或做微信官方编译 / 真机验证。密码找回、改密与撤销全部会话、账号注销、运维恢复界面、分布式限流和大规模负载验证仍待后续实现。没有上线服务与持久化备份前，不应向学习者宣称已支持线上账号永久保存。
