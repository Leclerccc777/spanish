# 开发说明

原生微信小程序与浏览器体验版共享 `miniprogram/data/` 和 `miniprogram/lib/learning.js`，避免课程与算法分叉。浏览器构建脚本把共享 CommonJS 模块包装进本地 bundle；无需前端框架或远程 CDN。

## 单文件 HTML 优先交付

`scripts/build-web.js` 继续生成静态站点，同时将 CSS 与三段经典脚本内嵌到 `dist/hola-spanish.html`。脚本按共享引擎 → 界面工具 → 应用顺序放在 body 末尾，确保页面容器已存在；转义脚本中的结束标签，避免 HTML 解析提前结束。不使用模块脚本、fetch 或远程资源，支持普通桌面浏览器的 `file://` 打开。

`npm run package:html` 通过 `scripts/package-html.js` 重建并复制为版本化交付 `releases/hola-spanish.html`；不要手改生成文件，每次源码更新后重新打包。站点仍部署 dist 中的 index.html 与独立资源；开发服务器的 CSP 不允许直接执行内联脚本，单文件交付用于下载后打开。

`tests/e2e/standalone.spec.js` 默认拦截本地导航，以生成文件原样响应，并将浏览器设为离线，验证无额外资源请求、真实作答、重载、词库搜索和 JSON 备份往返。云环境受管 Chromium 策略阻止 `file://`，此默认测试不声称覆盖该协议的存储行为。在允许本地文件的电脑上运行 `HOLA_STANDALONE_FILE=1 npm run test:e2e -- --grep 单文件` 可直接验收 file://；还应手工双击交付文件。

沿用 `hola-learning-v1` 与 version 1；HTTP 与本地文件不自动共享存储。换入口或更新路径前先导出，再导入。不能因 HTML 初次打开没有记录而重置原入口的进度。先完成浏览器验收，再安排微信官方编译与真机打包。

## GitHub Pages 发布

`.github/workflows/pages.yml` 在 main 推送或手动运行时构建网站，上传 `dist/pages` 并部署到 GitHub Pages。构建只用 Node.js 内置模块，无需 npm ci；构建任务仅 contents:read，部署任务另授 pages:write / id-token:write。首次需要仓库管理员在 Settings → Pages 将 Source 设为 GitHub Actions，普通工作流 GITHUB_TOKEN 不能代为启用未开启的 Pages。

`dist/pages/index.html` 与同次构建的 `dist/hola-spanish.html` 字节一致，内嵌资源避免 `/spanish/` 子路径引用站点根目录的问题；`.nojekyll` 表明无需 Jekyll。不要把带站点根路径引用的原始 web/index.html 直接当作项目站点首页。

预期地址是 `https://leclerccc777.github.io/spanish/`；需确认部署记录成功并打开真实页面后，才能声称已上线。线上沿用原记录格式，文件入口迁移到 HTTPS 入口需显式导入 JSON，原文件的存储不被覆盖。

## 共用练习交互

`lib/exercise.js` 维护名词和分级包的临时作答状态，以及带重音的答案检查。先检查答案再写入临时数组；最后一题只在保存成功后进入结果页，失败或重复点击不会增加作答次数。`showHint` 属于临时界面状态，不加入备份。

原生 `lib/exercise-page.js` 提供输入、重音按钮、提示、作答和翻题方法。页面通过 `itemKey`、`evaluate`、`grade`、`canPractice` 及保存后的回调提供差异；存储和平台方法显式传入，便于模拟测试。集中订正仍单独维护限次重排及首答统计，不能用整包评分替代逐项订正。

浏览器 `web/exercise-ui.js` 共用选项、输入、提示及反馈的 HTML，并统一转义文本；`app.js` 负责路由与保存。新增脚本须同时加入 `web/index.html` 和构建复制清单；新增共享模块须加入构建模块清单。

`data/drill-coaching.js` 按稳定包 ID 保存情景引导、短文中文大意、四条思路提示与开口迁移任务。提示引导寻找线索，不直接展示完整答案；新包必须补齐教学支架。详细规则仍放在原包中，避免另建一套覆盖规则的文案表。术语宜接在具体句子和意思之后，先让学习者知道为什么这样说。`showMeaning` 仅控制阅读页的临时展开状态，不进入备份，作答页不展示中文大意。

`data/drill-practice.js` 按相同包 ID 提供 `words`（三组原文短语 / 中文意思 / 本句用法）、`dialogue`（场景、三轮角色提示、个人替换要求）及 `newScene`（迁移任务、检查问题）。短语必须能在原文找到；解释不补出原文未说明的事实。对话给句子起点，留出学习者回答，迁移要改变实际场景而非只照抄范文。手工自查仍对应原写作任务，不能添加量规索引而误读旧勾选。

`showWords` / `showDialogue` 只存在于阅读页临时状态，换包或刷新默认收起，不增加备份字段。展开、收起与中文大意共存，保持未保存的草稿；个人对话和新情景文字可保存到原 `drillDrafts`，继续受前置关系、3000 字限制与保存失败保护。作答及集中订正仍使用原来的简短 glossary，不直接展示完整词组解释或个人对话。

## 修改课程

A1 在 `data/course.js`，后续阶段在 `data/course-extension.js` 添加单元、词条、课程与题目，给它们稳定且唯一的 ID，并补充 `sourceIds`、`references`。已有 ID 不要重新分配，否则已有学习记录会指向错误内容。更新测试中的数量与解锁要求；题目正确答案用从 0 开始的选项索引。

`expression-tasks.js` 生成各单元目标词、复习词、表达框架、允许检查的词形与原创范文。变位和复数需显式加入 `forms`；本地检查不做词干猜测，不得包装成语法评分。新增输出任务后验证范文符合公开形式要求。

新增权威参考页时，在 `data/sources.js` 记录官方 URL、机构、角色、核验范围和日期。先阅读正文，再填写核验状态。运行资料检查脚本只能验证当前网页响应，不替代课程专家审阅；若标题不符或出现挑战页，应人工诊断而非标为已核验。

## 记录格式

`version: 1` 下包含：

- `track`：`course`（默认）或 `bank`；旧备份缺省保持课内范围。
- `foundations[id]`：四步入门规则测验最佳分与次数；与每日打卡独立。
- `monthChecks[day]`：前四周任务的实际记录日期与 recall / focus / output 手工记录；沿用年度起点，未来天不能提前记录。
- `journey`：本地开始日期、`weekChecks[weekNumber]` 的日期和五项手工自检；未来周不允许记录。
- `nounPractice[wordId]`：三步名词练习的最佳正确率（0 / 33 / 67 / 100）和完整作答次数；不影响每日目标或词元确认。
- `nounMistakes[questionId]`：最后一次完整作答中的错项答案；下次完整练习答对对应题后移除。页面逐题反馈不写入进度，最后保存三步结果；保存失败留在提交入口。
- `drills[packId]`：补充分级包的最佳正确率与完整作答次数；前置包最佳分至少 75% 时开放后一包，不改变主课程。
- `drillMistakes[questionId]`：补充分级包最后一次完整作答的错项答案；订正后移除。
- `drillDrafts[packId]`：当前 text、可选 previousText（各最多 3000 字符）、revisions 与 checks（手工自查索引）；不评分，不参与解锁。
- `goal`：后续学习日的词汇数量目标。
- `reviews[wordId]`：间隔、到期日期、最后复习日期、复习次数。
- `lessons[lessonId]`：历史最佳分与练习次数。
- `days[YYYY-MM-DD]`：固定的当日目标、不同词元 canonicalId、达标课程 ID；恢复旧备份时合并重复语境。
- `mistakes[questionId]`：待订正答案、课程和日期。
- `wordPractice[wordId]` / `wordMistakes[wordId]`：词汇测验次数、答对次数与待订正答案。
- `expressions[taskId]`：当前草稿 `text`、最后提交 `submittedText`、更新时间、提交次数。保存草稿不会替换最后提交记录。
- `reviews[wordId].confirmed`：曾确认记住或测验答对，支持稳定解锁；之后遗忘会重排复习但不锁回后续单元。旧备份的非零间隔可恢复这个确认标记。

打卡由每日记录推导，不存储可直接点击改变的打卡标记。存储写入失败时，前端保留当前词卡或练习结果提交入口，不显示虚假的已保存进度。本次新增字段保持 version 1，旧备份缺少可选字段时补空；将来不兼容地修改 schema 时应实现迁移并提高 version，不能直接丢弃已有记录。

## 微信验证

Node 测试中用模拟 `wx` 对象验证页面控制逻辑，不等同于微信运行时。WXML、WXSS 和平台 API 的最终兼容性须在微信开发者工具与真机检查。当前无微信身份授权登录、云函数或外部音频 API；新增可选账号密码服务见文末，内置音频继续使用本地分包。

原生页面采用默认导航栏与 5 个原生 tab，额外词卡、语法、词汇测验和表达页通过 `navigateTo` 打开。现有音频来自本地分包，不需要音频服务域名；后续若新增远程音源，需确认授权、配置真实 HTTPS 域名并验证微信播放行为。

## 扩展库重建与兼容

`scripts/build_lexicon.py` 只下载 `docs/lexicon-sources.json` 固定提交的三个文件，验证大小和 SHA-256 后再处理。输入在 `/tmp/hola-lexicon-sources`，不提交几十 MB 的原始词典。生成 `data/lexicon/entries.js` 紧凑行数组与 `docs/lexicon-build.json`；`check_lexicon.py` 检查去重计数、生成哈希、表达覆盖和小程序源码包预检。

新词 ID 为词元 NFC 字符串的 SHA-256 前 12 位，排序变化不重编号；原 `w1`–`w320` ID 保留。`course.curriculumWords` 是课内 320 词卡，`course.words` 包含全部可学习卡片（6503 张，含 3 张复用卡），统计使用 `course.lexicon.catalogue`（6500 个词元），不可用卡片总数充当词汇量。

`data/lexicon/index.js` 构造阶段与词包；`tasks.js` 每 5 个新词生成一组表达任务。首组用词包 ID，后续组追加 `-2` 等后缀，每组草稿独立保存。扩展 `modelKind: scaffold` 只能标为待填写框架，不能当作完成范文；检查所有新增词有目标任务，框架不能通过完整输出条件。

词库页面每次仅渲染 30 词及 6 个词包，微信 `setData` 不一次传入全部词库。扩展词义采用英文原义和英中提示，来源文件校验与内容人工校对状态分开；不要自动将新词标成 `reviewed`。许可证保留在仓库 `LICENSES/`，应用资料库提供署名说明链接。

## 新手与年度路线

`data/foundations.js` 提供 4 个原创微课和 16 题，内容参考 PCIC 发音/语法与 DPD tilde/el。`data/year-plan.js` 将已有 A1–B1 24 个单元分配到前 48 周，再安排 4 周复盘；第 365 天单独作学习档案与外部评价建议。`lib/journey.js` 处理基础评分、合法日历日期、开始日期、周自检、旧备份恢复。避免用日历直接解锁单元或把周自检认定为等级达标。

两个入口分别是 `pages/foundations/index` / `pages/year/index` 和浏览器 `#foundations` / `#year`。基础练习最佳分不回退；存储失败必须留在可再次提交的位置。年度周次是预览与建议，实际课程仍使用 `isUnlocked`；五项自检可反选且不改变日打卡。

更新课程或模块后同步 `scripts/build-web.js` 的模块表；独立新增内容不应改变原词元稳定 ID 或旧备份 version。原生与浏览器发音练习可播放内置合成音，但不自动评分；6500 个词条全部有内置音频；设备音色只作为未来缺失文本的提示性降级。

## A1 名词三步练习

`data/noun-practice.js` 仅引用已有词 ID，为首批 8 个名词保留单复数冠词、语法性、短语、原词典链接与 PCIC / DPD 规则引用；不修改 `vocabulary-review.js` 或扩展词库。新增搭配与题目待教师审稿，详见 `docs/NOUN_PRACTICE.md`。

`lib/nouns.js` 的指定答案检查支持 NFC、大小写、连续空格和句末标点，重音与 ñ 必须准确。它不做语法推断或开放文本评估。三题先完整验证再更新进度，完整练习的最佳分不回退；错项依据最后一次作答更新。`learning.restore` 为旧 version 1 备份补空字段，过滤未知 ID 与无效分数。

原生入口为 `pages/nouns/index`（可用 `?id=w24` 直接查看一个词），浏览器为 `#nouns` / `#noun/w24`；无需课程解锁，可从性数微课继续练。未保存的中途答案只在当前页面内存中，离开后重开；末题保存成功才显示已保存结果。微信与浏览器词卡及课内词汇详情同步展示这批词的词形信息。

## A1–B2 递进练习

`data/drills.js` 与 `data/drill-extension.js` 提供 24 个稳定 ID 学习包，每级 3 个核心 + 3 个巩固包。每包包括前置包 ID、所用课程 ID、复用词、中文规则、例句、短文及词语提示、四种题型和个人表达量规；引用从对应课程继承，不新增来源核验结论。新增材料为原创，待教师审稿。

`lib/drills.js` 沿显式 previousId 关系回溯历史最佳分推导开放状态，并拒绝循环或缺失前置；原核心链保持不变；后续内容可预览，直接评分或保存后续草稿被拒绝。四题完整校验后更新最佳分与错项，不允许稀疏或缺题答案。正确率仅检查公开允许的词形与受控改写，支持 NFC、大小写、连续空格、开头问号 / 感叹号与句末标点，保留重音和 ñ。假设包显式接受 tuviera / tuviese 两种形式。

原生 `pages/drills/index` 和浏览器 `#drills` / `#drill/a1-place` 共享引擎。草稿与四题结果分开保存；每份只保留一个 previousText，相同文字不增加保存版本，改变文字时清空自查；保存非空且未改动的草稿后才能对照范文，修改后需再次保存。保存失败保留当前答案或未保存草稿，重复点击结果提交不增加次数。中途题目保存在页面内存，离开后重开；草稿需要点击保存。

旧 version 1 备份缺少新字段时补空，恢复时只保留已知 ID、0 / 25 / 50 / 75 / 100 分、有效次数与限制内字符串。内容的前置关系固定，不用日期或自由表达草稿判定语言等级。新增或改动包时保持 ID 稳定，需同步模块构建表和相应验证；不要修改已经用于记录的题 ID 含义。

## 视觉主题

浏览器样式在 `web/styles.css`，微信共用样式在 `miniprogram/app.wxss`；原生导航栏和 tab 配色另在 `app.json`。当前采用亮绿 `#58cc02`、白色、浅蓝 `#e9f7ff`，主按钮用深色字 `#173d00` 保证清晰，次按钮和导航使用蓝色文字 `#075b86`。卡片及按钮用底部阴影建立层次，按下时降低阴影；原生按钮通过 `hover-class="button-press"` 实现反馈。

保持正确、错误与未解锁状态文字明确，避免仅靠颜色区分。浏览器键盘焦点使用深蓝轮廓，减少动态效果偏好下取消过渡；禁用按钮不使用主色或按压动画。配色修改后运行浏览器交互测试、检查手机布局并用 `capture-preview.js` 更新截图；截图使用 Asia/Shanghai 时区，应用仍按实际设备的本地日期记录。

## 集中错项订正

`lib/drill-review.js` 只从已开放包抽取存在的错项，返回带原包、阅读和题型上下文的队列，最多 12 个初始错项。订正通过 `evaluateDrillAnswer` 复用指定答案与标点规则，只更新 `drillMistakes`，不更新 `drills`、复习、打卡或词量。已经移除的错项重复提交不会重新生成错项。

原生 `pages/drillreview/index`、浏览器 `#drill-review` 保存成功后才显示反馈；错项每轮至多重排一次，首次统计仅计每个题 ID 的第一次作答。中途刷新重新开始本轮统计，已保存的订正仍保留。草稿修订和自查调用 `revertDrillDraft`、`setDrillChecks`，旧备份在 restore 时补充默认字段并过滤非法历史 / 自查索引。

## 前四周每日任务

`data/first-month.js` 提供 28 天 / 84 项固定 ID 提示及已存在的内容入口。`lib/first-month.js` 使用年度开始日，按设备本地日期计算建议任务日；超过第 28 天后可回顾任意前四周任务。记录只写 monthChecks，不能修改课程、词量、间隔复习或打卡。

`pages/firstmonth/index` / `#first-month` 允许所有任务预览；开始年度计划后，任务日不晚于实际经过天数时才可勾选。过去任务记录实际勾选当天日期。restore 过滤非法日期、未知任务、重复任务、超过 28 的键及记录日期不足以支持的未来任务。配套课页可播放内置音频，但没有发音评价，手工任务不能自动填充年度听力自检。

## 读取失败与未知版本保护

原生 storage.read 严格读取版本；load 的空状态仅供显示，不用于提交。commit 重新严格读取，失败时不执行 action 或写入，导出也使用严格读取，防止把旧数据当成空进度覆盖。导入兼容备份仍是用户明确确认的替换操作。

浏览器 readStored 检查 JSON 与版本，失败时保留 storageFailed；此时 commit 先尝试重读并返回，重读成功后用户再次操作才保存。进度页可主动重读，未知版本 / 损坏 JSON 也不会导出成空备份；明确导入成功后清除保护。其他窗口的坏记录事件同样触发保护，正常记录事件可恢复。

## 补充练习进度与建议

`lib/drill-progress.js` 只读取记录，按已知题包 ID 汇总每级总包数、已练、规则题达标、已开放、可订正错项、非空草稿和自查勾选。未知记录不会充当新包数。手工任务只数已知 28 天中的完整三项，不改变任何学习字段。

首页在有可订正错项时优先建议集中订正，否则使用真实前置关系建议下一包；全部达标后提供回顾入口。进度页分别显示主课程与补充练习，不能把自查或手工任务拼成能力分。原生分级页支持 level 查询参数，浏览器按指定等级打开；后续包仍保留预览门槛。

## 与材料对应的周指南

`data/week-guide.js` 的 weekGuide(number) 根据既有年度周次、课程词汇 / 规则 / 题目、课内表达与分级短文生成七天操作提示。52 周均有词卡、语法、阅读、口头表达、书面修订与回顾入口；复盘周降低新词期待，不生成新的能力成绩或自动勾选。

读取材料时优先选择本等级、单一课题对应的短阅读，再使用既有复合课题；课程与题包仍按各自实际前置开放。配套短文已有合成音频，可先听后读；学习者实际听完并完成练习后再自行勾选，单纯阅读或播放点击不能代替听力自检。它只生成提示，不改学习状态或备份格式。

## 同级建议与阅读进阶

`data/drill-path.js` 保存建议顺序、各级起点 / 阅读方法 / 本级目标，以及按原包 ID 定位的阅读问题、原文依据和意思解释。`data/drill-articles.js` 在每级建议末包提供多段文章、词组、三项自查和回应任务；不修改原阅读题及其答案。引用的依据必须是原文片段，词组能在文章中定位；教师审核状态仍为待审。

`lib/drills.js` 维护按 `studyOrder` 排序的只读视图。`drillProgress` 用于菜单展示；`nextDrillPack` 有当前包时先找本级已开放且未达标的包，否则按建议顺序找下一包。原 `drillPacks` 顺序和 `previousId` 链保持不变，旧核心备份不会被新增推荐顺序锁回。建议顺序必须能从空记录实际逐包完成，并保持所有旧题、原写作任务和自查索引不变。

浏览器四步按钮用局部滚动和焦点定位，不改 hash、不重建编辑器；原生使用 `pageScrollTo` 的 selector。`showEvidence` / `showArticle` / `showArticleEvidence` 与原阅读提示同属临时状态，换包或刷新收起。浏览器合并提示切换分支，重渲染后恢复操作按钮的焦点；各提示仍保留未保存文本。所有草稿继续走原 `saveDrillDraft` 和严格存储保护，不增加成绩或备份字段。

长文章入口可在锁定包预览，但草稿保存仍受原前置控制。文章的三项阅读自查只展示问题与参考，不混用旧 `checks` 索引；回应可写入同一草稿，界面明确原自查只对应原写作任务。新增数据模块须列入浏览器构建清单；Pages 与单文件从同一构建生成。

## 音频与平行题

语音生成、来源、覆盖与分包规则见 [AUDIO.md](AUDIO.md)。浏览器 `audio.bundle.js` 包含 MP3 data URL，`audio.js` 共用播放、慢速、停止和设备朗读降级；`web/index.html` 与构建清单都要列入新脚本。开发服务器 CSP 显式允许 media data:，Pages 与离线 HTML 全部内嵌。原生 `lib/audio.js` 用 `loadSubpackage` 和 `createInnerAudioContext`，用代次标记防止过期加载启动，离页销毁播放器；不读写学习状态，不引入音频服务器域名。

`data/*-variants.js` 为四类练习按原题 ID 提供一套平行题；原始题和前置关系保持不变。`lib/variants.js` 验证 form 为 0 / 1，按已保存完整作答次数交替。会话开始时固定 form 与题目，检查反馈、整包评分和保存失败重试都使用同一 form，不能在最后提交时再根据最新次数猜题。题组内的选项、答案、解释与阅读短文必须共同更新；并非只打乱选项次序。

`lessonQuestions`、`foundationQuestions`、`nounQuestions` 和 `drillQuestions` 是显示与评分的共同入口。所有评分 API 末尾可选 form 默认 0；旧调用与备份仍按原题。`mistakes`、`nounMistakes`、`drillMistakes` 可选 form:1 标识当时的平行题；restore 只接受 1，其余按原题，题目 ID 和 version 1 不变。错题列表使用记录的题组显示旧答案，集中订正用另一题组，并将新的错误与实际题组一起保存；正确只移除错项，不增加原包成绩。每轮至多重排一次，首次正确率仍单独统计。

词义题从同单元 / 同词包的候选中选干扰项；极小词包不足时补充同等级课内词，在本页内记住上次选项，下一次优先加入未出现的释义；词元、拼写与首次统计不变。两套语法题是有限轮换，不属于无限生成；新增题仍待教师审稿。


## 全词库语音与词组核对（2026-10-17）

`audio-texts.js` 从全部 `course.words` 去重取原文，并加入入门例词、语法例句、短文、文章段落、72 组短文词语、21 组文章词语和 8 个名词的单复数 / 搭配 / 完整句。共 6788 个精确文本；不能用英语原义或中文提示生成西语音频。斜杠分隔的阴阳性形式分别送入模型生成 PCM，再用 180 ms 停顿合并，防止句界处理遗漏后一项；词元 ID、教学词量和旧备份不变。

生成器核对固定模型哈希，输出目录保存参数并拒绝混用；默认两个独立进程各用一个推理线程，可用 `--workers 1` 降低资源占用。模型与断点缓存放在工作区的 `.audio-cache/`（Git 忽略），避免环境重建时丢失 `/tmp` 进度；缓存 PCM 用于核验或重新编码，MP3 通过临时文件完成后改名，避免中断留下半个成品。孤立词初次生成短于 250 ms 时补句末标点并按原长度降低速度重合成，仍短于 120 ms 则补独立强调语气，仍不满足时直接报错；不会只补静音通过检查。16 kHz 单声道 / 24 kb/s MP3，仅移除首尾多余静音，保留内部停顿和两端约 80 ms 余量。最终音频与分包必须全部通过大小预检，不能为了通过检查而遗漏词条。

`package-audio.js` 在修改发布文件前读取并校验全部素材、估算主包和总包大小；若分包里有不属于旧生成清单的文件则拒绝操作，避免删除或遗漏包体预算；随后按清单移除废弃 MP3。每个音频分包不超过 1,500,000 字节，主包小于 2 MiB，总体小于 20 MiB；官方编译仍需单独验收。浏览器 HTML 内嵌同一批素材；更新后重新打包，避免旧的 493 段包与新清单混用。

词库的详情、短文词组、文章词语和名词搭配提供试听，预览不解锁、不自动打卡。原生使用 catchtap 防止播放按钮触发外层展开；搜索、翻页、关闭词组及离页停止旧音频。词组释义应只翻译选中的片段，外层语法含义放在说明中；例如 lo había presentado 本身不含“是否”，“是否”来自 no sabía si。

## 账号服务与每周表达路线（2026-10-20）

实现、部署步骤、接口与边界见 [ACCOUNTS.md](ACCOUNTS.md)。`server/accounts.js` 使用 Node 内置 SQLite、事务注册、scrypt 密码派生、随机会话与 revision 条件更新。`server/start.js` 是独立服务入口；`scripts/server.js` 仅在 `HOLA_ENABLE_ACCOUNTS=1` 时为本地联调启用。服务需要 Node >=22.13，推荐 24；纯静态功能仍可在 Node 20 构建。服务库不依赖微信或浏览器运行时。

`lib/account.js` 共用账号客户端，通过存储和请求适配器注入平台 API；原生 `account-runtime.js` 封装 wx.request，App 启动时配置 storage，浏览器直接适配 localStorage / fetch。本机保存为同步写入，网络上传在其后进行，失败不回滚已保存学习数据，也不能声称已上云。每份本机进度同时包含 pending / revision；写入失败不得前进练习，普通保存不能覆盖未知版本。手工导入允许明确替换并另存替换前记录。所有 JSON 学习备份仍只包含原 progress。

构建必须列入 `lib/account`；`HOLA_ACCOUNT_API` 仅接受 `/api` 或以 `/api` 结尾的 HTTPS 地址。Pages 工作流从同名仓库变量注入，默认空字符串；微信地址在 `config.js`，不允许学习者任意切换到未知服务器发送密码。file:// 强制禁用账号，离线学习无网络依赖。后续真实部署后才可在 README 声称账号服务已开放。

周指南第 4 天按对应短文提供真实词组与阅读问题，第 5 天打开相同题包的个人对话和迁移任务；综合复盘周优先选同级文章。七天结构和第 6 天课内写作不变，日期不解锁任何课程或自动填写自检。没有新增教学材料音频，仍使用既有合成音清单；只读文字不能认定听力完成。

## 头像入口、账号统计与学习位置（2026-10-22）

浏览器 `#account` 展示详情，右上角头像根据身份打开 DOM 菜单或原生 dialog。dialog 在应用根节点外，开关菜单只改 hidden 和 aria-expanded，不触发整页 render；关闭后返回头像焦点。表单错误在弹窗内反馈并清空密码，提交中阻止重复提交 / 关闭。菜单按 WAI-ARIA menu 操作方向键与 Escape，点击外部或焦点离开可关闭。退出 / 登录切换前检查未保存的文字与中途练习；取消时保留当前编辑器。

`lib/profile.js` 汇总已有记录，不写成绩：词汇正确率采用 wordPractice.correct / attempts，包含重练；语法与分级用已练内容的 bestScore 平均值，明确命名历史最佳均分。关卡仍由 unitProgress / isUnlocked 决定，手工记录和日历不改变开放条件。空记录返回 null 正确率，界面显示尚未练习；读取失败时不展示临时空统计。

新增可选 `resume: {kind, id? , day? , week?}` 沿用 version 1：restore 只保留已知课程 / 题包 / 表达 / 名词 / 入门 ID 和合法范围的计划日周；不保留 route 或任意 URL。服务端与两端 restore 均复用同一模块。登录状态下进入开放内容时保存位置，已知成绩不会被位置替换；普通访客预览不新增存储写入。账户登录后 learningDestination 重新核对真实前置与日期，已完成课程转向当前未完成关；旧备份没有 resume 也能从成绩继续。词卡继续由间隔复习队列安排，练习中途尚未保存的题目答案不属于跨设备恢复范围。

构建模块表需包含 lib/profile；更改后重建 Pages 和单文件，更新头像、弹窗及详情的桌面 / 手机验证。不要把尚未部署的账号 API 描述为线上已开通。

## 云托管入口（2026-10-22）

`server/start.js` 导出 startAccountServer 供真实 HTTP 测试，也可由 npm run start:accounts 启动。默认 HOST=127.0.0.1 保留自建服务器反向代理方案；云托管配置 HOST=0.0.0.0、使用平台 PORT，并将 HOLA_ACCOUNT_DB 指向持久化挂载路径。`/healthz` 只检查 SQLite 连接并返回 ready / unavailable，HEAD 不返回内容；服务器关闭后释放数据库连接。Render 配置和接入步骤见 DEPLOY_RENDER.md，不在获得真实服务 URL 前启用前端账号地址。
